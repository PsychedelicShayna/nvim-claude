# Domain docs

Root CONTEXT.md holds this project's vocabulary, invariants, and accepted domain decisions. SPEC.md defines intended product behavior and acceptance criteria.

## Before exploring

Read CONTEXT.md before domain exploration and SPEC.md before proposing behavior changes. Keep agent-facing domain guidance in CONTEXT.md and docs/agents rather than adding a separate decision directory or context tree.

Implementation must await explicit owner instruction. A domain proposal, specification, or prepared comparison baseline does not authorize starting it.

## Vocabulary and decisions

Use the terms defined in CONTEXT.md in issues, proposals, hypotheses, and tests. Surface a genuine glossary gap instead of inventing a competing synonym. Distinguish owner decisions from engineering proposals and unresolved questions.

If a proposal contradicts an accepted decision or invariant in CONTEXT.md or SPEC.md, name the passage and explain the conflict. Keep proposals and unresolved questions distinct from owner decisions. Update the relevant existing document when the owner settles a decision.
