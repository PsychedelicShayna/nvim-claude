# Domain docs

This repository uses a single-context layout.

## Before exploring

Read root CONTEXT.md for the glossary and invariants. Read SPEC.md when changing intended behavior. Read relevant entries in docs/adr/ when they exist.

If a domain document or ADR directory is absent, proceed silently. Create ADRs when a real architectural decision is made, not as empty scaffolding. This project does not need a CONTEXT-MAP.md or per-package context trees.

## Vocabulary and decisions

Use the terms defined in CONTEXT.md in issues, proposals, hypotheses, and tests. Surface a genuine glossary gap instead of inventing a competing synonym. Distinguish owner decisions from engineering proposals and unresolved questions.

If a proposal contradicts an ADR, name the ADR and explain the conflict. Do not silently replace an accepted decision.
